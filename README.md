# 小朋友下樓梯（stair-kids）

一直往下跑的經典下樓梯遊戲。只有左右兩個方向，沒有跳；畫面上緣的天花板會越玩越快地追下來，
下得越深分數越高。**目前進度：M0（單機一人挑戰一局可玩）。**

規格唯一來源是 [`規劃書.md`](規劃書.md)，本檔只寫「怎麼跑起來」與「M0 做了什麼」。

---

## 怎麼玩起來

**最簡單**：雙擊 `啟動遊戲.bat`（會自己找 Node，開好瀏覽器）。

**用命令列**：

```
npm start
```

然後開 <http://localhost:3060>。

**完全不裝 Node 也可以**：M0 只有單機，直接用瀏覽器打開 `public/index.html` 就能玩
（伺服器只負責發靜態檔案與 `/health`，線上模式要到 M2 才接上）。

埠號固定 **3060**（3000／3010／3020／3030／3040／3050／3090 已被 `C:\Eric\AI Agent` 底下其他遊戲佔用）。
要改就設環境變數 `PORT`，或抄 `.env.example` 成 `.env`。

## 怎麼驗

```
npm run verify        # 下面三支全部跑一次
npm test              # tests/verify.js       規則核心單元測試
npm run test:stairs   # scripts/stairs-check.js  一萬層樓梯驗收
npm run test:match    # scripts/match-check.js   單機一局跑完
```

三支都是零依賴的純 Node，不需要瀏覽器。

## 操作

| | |
|---|---|
| 鍵盤 | `←` `→` 或 `A` `D` 左右移動；`Esc` 暫停選單（繼續／重新開始／回首頁） |
| 手機平板橫向 | 左下兩顆大按鍵 |
| 手機平板直向 | 左鍵在左下、右鍵在右下（兩手拇指各一邊） |
| 設定 | 右上角齒輪（唯一入口，不重複放進暫停選單） |
| 幼幼班 | 沒有終點，右上角「結束這局」隨時收局看成績 |

## M0 做完了什麼

- **規則核心** `public/js/rules.js`：純函式、無 DOM、無 socket、無計時器。
  左右移動與重力、掃掠落地、五種階梯、鏡頭跟最深存活者（有追隨速度上限）＋隨時間加快的保底下捲、
  天花板把人往下推並扣血、掉出畫面下緣摔死、血量與深度計分、每 100 公尺換世界、四段難度、
  角色朝向（左／右／正面）、勝負判定（含對戰與線上的分支）、
  玩家推擠 `resolvePush`（M1 才用得到，但介面與測試先做好）。
- **樓梯生成** `public/js/stairs.js`：可注入種子、無限往下、**可達性保證**、
  連續同款上限、每 4 層保底安全落點、每 12 層喘息階、彈簧不接在刺階正下方。
- **單機一人挑戰**：首頁三顆大按鈕 → 選角色與難度 → 倒數 2 秒 → 玩 → 結算（含「這局統計」）→ 再玩一次。
- **美術**：8 隻小朋友與六套世界主題，**全部手繪向量 SVG，沒有任何 emoji 文字美術**。
  角色是頭＋身體＋雙手＋雙腳＋漸層，六組姿勢（站／走／下墜／彈起／踩刺／被頂／暈眩）。
- **音訊**：木琴童謠風 BGM，六個世界換樂器變奏，速度倍率越高節拍越快；十種音效。
  BGM 與音效音量獨立，首次手勢後才解鎖。
- **設定彈窗**：BGM／音效（各自開關＋音量）、震動、減少動態、色彩輔助、深度輔助線、
  清除本機紀錄、恢復預設。焦點鎖定、Esc 關閉、重進保留。
- **本機紀錄** `localStorage`：各難度最深深度與日期、最深世界、常用角色、上次的暱稱與角色。
- **RWD**：桌機寬版／平板直橫／手機直橫都驗過，資訊欄在左邊且刻意小，直向壓成上方薄狀態列。
- **伺服器** `server.js`：零依賴，靜態檔案 ＋ `/health` ＋ `/api/presence` ＋ 自寫 WebSocket（`lib/ws.js`）
  的最小端點，M2 才接上房間迴圈。

**M1 之後（AI、線上、觀戰、聊天）都還沒做**，但規則核心已經留好共用介面：
`createMatch / stepMatch / makeStairs / resolveLanding / resolvePush / applyCeiling / checkResult`，
AI 與線上都只要送 `{ dir: -1 | 0 | 1 }` 這種和真人一模一樣的輸入。

## 待 Eric 確認的幾件事

規劃書裡有幾處內部不一致或沒寫到的地方。M0 先照下面的做法實作，**每一項都是一行常數就能改**，
不同意就說一聲。

### 1. 彈簧強度：「彈回上一層半」和「9 格／秒」互相矛盾（重要）

- §0.1 決策表寫 **「溫和：彈回上一層半」**，§1.3 參數表寫 **「向上彈初速 9 格／秒」**。
- 但 9 格／秒 在重力 30 格／秒² 下只彈得起 `9² / (2×30) = 1.35 格`，
  而層間距是 2.0～3.0 格 —— 換算下來大約只有 **半層**，不是一層半。
- 要真的彈回一層半（3.0～4.5 格）需要 **約 15 格／秒**。
- **M0 先照 §1.3 的具體數字實作 9 格／秒**（比較溫和、比較安全）。
  要改成一層半就把 `public/js/rules.js` 的 `C.SPRING_VY` 從 `9.0` 改成 `15.0`
  （`tests/verify.js` 是用公式驗的，改了數字測試照樣會過）。

### 2. 輸送帶與彈簧的出現比例，規劃書沒給

§1.7 的難度表只給了刺階與假階的比例。M0 先假設 **輸送帶 14%、彈簧 10%，四段難度都一樣**
（只有刺階與假階跟著難度變），在 `public/js/stairs.js` 的 `C.BELT_RATE` / `C.SPRING_RATE`。
實測一萬層的實際比例（連續性限制會壓低一點）：

| 難度 | 普通 | 輸送帶 | 彈簧 | 刺 | 假 |
|---|---|---|---|---|---|
| 幼幼班 | 78.6% | 12.3% | 9.1% | 0% | 0% |
| 簡單 | 63.9% | 13.1% | 8.5% | 6.9% | 7.6% |
| 普通 | 55.4% | 12.9% | 8.2% | 11.1% | 12.5% |
| 困難 | 48.6% | 13.1% | 7.9% | 15.1% | 15.3% |

### 3. 可達性算式裡的「水平距離」沒有定義

§3 寫「新階與上一層的水平距離不得超過 落下時間 × 6 格／秒 × 0.8」，但沒說是中心距還是邊緣距。
M0 採用 **兩階水平區間的邊緣距離（重疊算 0）**，理由是玩家站在上一階時就能先走到靠近的那一端，
這才是物理上真正要跨越的距離。

同時多做了一件規劃書沒寫、但不做會有死路的事：**新階必須從「上一層的每一階」都走得到**，
不是只從其中一階。因為上一層偶爾會有兩階，玩家可能站在任何一階上。
這條連帶推出「同一層兩階最遠只能隔 6.0 格」（`C.TWO_STEP_MAX_SEP`，推導寫在程式註解裡）。
`scripts/stairs-check.js` 會用貪心模擬走完一萬層，四段難度目前都是 **零死路**。

### 4. 輸送帶「順向」的速度規劃書沒寫

§0.1 只給了逆向的 `6 − 3 = 3 格／秒`。M0 採用相加：**順向 6 + 3 = 9 格／秒**。

### 5. 天花板扣血間隔比刺階無敵時間還短

困難難度是每 0.4 秒扣 1 顆，但踩刺的無敵是 0.6 秒。
依 §1.5「期間不再受**同類**傷害」，M0 把兩種傷害分成各自獨立的計時：
踩刺有 0.6 秒無敵、天花板照自己的間隔扣，互不影響。

### 6. ~~被天花板頂住時會不會被壓穿階梯~~（已定案，並改掉了三條決策）

Eric 後來指定：**被天花板頂到要自動被往下推**，而且**掉出畫面外要直接墜落死亡**。
這兩件事合起來是一套一致的設計，但會動到 §0.1 決策表的三條，已經照著改完：

| 原本的決定 | 改成 |
|---|---|
| 鏡頭跟最深存活者（瞬間跟上） | 鏡頭跟最深存活者，但**有最高追隨速度 8 格／秒**（`C.CAMERA_CATCHUP`） |
| 唯一的死法是血歸零 | 再加一種：**掉出畫面下緣直接淘汰**（結算標成「摔下去了」） |
| 被頂住持續扣血（站著被夾住） | 被頂到**推穿腳下的階梯往下掉**；扣血改成累計總接觸時間 |

- 為什麼鏡頭要加上限：原本鏡頭瞬間跟上，玩家永遠被鎖在離上緣 12 格的位置，
  實測連續踩空 20 秒、掉了 355 公尺都還在畫面正中間，**根本掉不出去**。
  加上限之後，自由落體最快 18 格／秒、鏡頭最快 8 格／秒，追不上的那 10 格／秒
  就是你往下沉的速度。實測**連續踩空約 16 格（5～6 層）就會摔死**。
- 為什麼扣血要改成累計：天花板會把人推穿階梯，所以接觸永遠是斷斷續續的
  （實測平均一次 0.15 秒、最長 0.4 秒）。要求「連續」接觸滿一個間隔的話就永遠扣不到血，
  §0.1 的「被上方天花板刺頂住持續扣血」等於被刪掉 —— 原地不動 40 秒只掉 4 顆血還死不了。
  改成累計總接觸時間之後，原地不動會在 25～104 秒內死掉（依難度），壓力才回來。
- **幼幼班例外**：鏡頭沒有追隨上限（永遠追得上），所以沉不出畫面、不會摔死，
  維持 §0.2 的「鼓勵式不死」。
- **附帶影響**：§7.1 原本說手機橫向要「縮短可見高度到 14 格並放大角色」，
  但摔死的判定線就在 18 格，看不到判定線會死得莫名其妙，所以手機橫向也改成一律顯示 18 格。
  要改回去是 `app.js` 的 `applyRenderOptions()` 一行。

### 7. 幼幼班的 20 顆愛心其實一滴都不會掉

幼幼班不出刺階、不出假階、天花板也不扣血，所以血量純粹是裝飾。
M0 照決策表照做（顯示成「愛心 × 20」），只是提醒一下這是必然結果。

### 8. `makeStairs` 放在哪一支

§9 的檔案結構把樓梯生成放 `stairs.js`，§4.3 又把 `makeStairs` 列在 `rules.js` 的介面裡。
M0 的做法：實作在 `stairs.js`，`rules.js` 直接轉出 `Rules.makeStairs`，兩邊都叫得到。

## 版控與部署

- 本機 git 已經建好，繁體中文 commit。**公開 GitHub repo 等 Eric 點頭再建，還沒有 remote、沒有 push。**
  要建的時候（repo 名 `stair-kids`）：

  ```
  git remote add origin https://github.com/<帳號>/stair-kids.git
  git push -u origin main
  ```

- 伺服器走 Render 免費方案（`render.yaml`，健康檢查 `/health`）。
- 前端走 GitHub Pages（`.github/workflows/pages.yml`），建置時由 repo 變數 **`GAME_SERVER_URL`**
  注入 `public/js/config.js`。server URL **只有 `config.js` 這一個入口**，
  不硬編碼、不回退 localhost；`scripts/inject-server-url.js` 也會拒絕 localhost。
- 大廳整合（`game-lobby/config/games.json` 加一張 `id: stair-kids`、`localPort: 3060` 的卡）排在 M4。

├─ server.js                零依賴 HTTP ＋ /health ＋ /api/presence ＋ WebSocket 端點

│  ├─ index.html  css/style.css
│  └─ js/

│     ├─ svgui.js           愛心、方向鍵、階梯圖示、Modal
